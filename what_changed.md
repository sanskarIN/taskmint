The benchmark audit found that the first benchmark harness used a later fixture-style benchmark interface while TaskMint pins Vitest `4.1.10`.

- `import { bench, describe } from 'vitest'`

### 2. Strict datetime parsing; impossible timestamps no longer roll over silently

JavaScript `Date` can normalize impossible calendar values instead of rejecting them. For example, an impossible February date can become a March date.

Created `src/domain/datetime.ts` with `parseStrictDateTime(value)`.

The parser validates before accepting a timestamp:

- year
- month range
- actual days in month
- hour
- minute
- second
- optional timezone offset components
- final JavaScript Date parse result

`src/domain/task.ts` now uses this parser for task reminders. An impossible reminder is rejected with `task-reminder-invalid` instead of silently changing date.

`src/domain/validation.ts` now uses the same strict parser for:

- `reminderAt`
- `completedAt`
- `archivedAt`
- `createdAt`
- `updatedAt`
- backup `exportedAt`

New `tests/datetime.test.ts` verifies:

- `2026-02-31T10:00` is rejected
- interactive impossible reminder creation is rejected
- valid leap-day input is accepted
- offset timestamps canonicalize correctly
- impossible backup timestamps are rejected
- TaskMint's own exported ISO timestamps remain valid

### 3. CSV tag-version compatibility repaired

A compatibility ambiguity remained after introducing structured `json:` tag cells.

A legitimate old CSV could contain a legacy tag such as `json:release`. If every `json:` prefix were interpreted as structured JSON, that old file could fail or change meaning.

Current behavior:

- Structured `json:` decoding occurs only when the row explicitly carries TaskMint's `taskmintEncoding=safe-text-v1` marker.
- An unmarked legacy row continues to use pipe-separated tag semantics.
- Legacy `json:release|stable` therefore imports as `['json:release', 'stable']`.
- New TaskMint-marked rows retain lossless JSON-array tag encoding.

Also hardened CSV row error containment:

- Detailed wrapped causes are included only for known `TaskMintError` values.
- An arbitrary infrastructure/internal `Error.message` is replaced with generic `Invalid task data.` before entering a stable CSV error.

New `tests/csv-compat.test.ts` covers legacy prefixes, marked structured rows, malformed marked structured tags, and unsupported encoding versions.

Key commits:

### 5. Strict CSV quote placement

The CSV parser still accepted malformed input in two ways:

- a quote embedded inside an already-unquoted field
- arbitrary characters after a quoted field closed

This could silently reshape malformed input instead of rejecting it.

Added typed error:

- `csv-invalid-quoting`

`parseCsv(...)` now tracks whether a quoted field has just closed. After a closing quote, only a delimiter or record ending is accepted. Quotes cannot begin after unquoted content is already present.

Valid escaped quote behavior remains supported.

New `tests/csv-quoting.test.ts` covers:

- embedded quote in unquoted field => reject
- trailing text after closing quote => reject
- escaped quotes inside quoted field => accepted

### 7. One deterministic manual-order rule across every path

Manual list sorting, drag reordering, and keyboard reordering previously did not all use the exact same tie-breaking rule.

`src/domain/order.ts` now owns:

```ts
compareTaskOrder(first, second)
```

The comparator sorts by:

1. numeric `order`
2. task ID when numeric order ties

This comparator is now used by:

- manual list rendering
- drag reordering
- keyboard reordering

This prevents a duplicate-order task set from rendering one way and being targeted/reordered another way.

### 8. Duplicate persisted order slots are normalized while preserving visible order

Even with deterministic tie-breaking, a deeper problem remained: if two tasks actually share the same numeric `order`, moving one can become a no-op because both occupy the same numeric slot.

Added:

```ts
normalizeDuplicateTaskOrders(tasks, step = 1000)
```

Behavior:

- scans for duplicate numeric order values
- returns the original array unchanged when orders are already unique
- if duplicates exist, sorts using the deterministic comparator
- assigns unique stepped numeric slots in that exact visible order

Applied to:

- JSON backup validation
- IndexedDB task reads

This preserves the visible order while making subsequent keyboard/drag movement persistable again.

`tests/order.test.ts` verifies:

- deterministic visible order is preserved
- normalized orders become unique
- tied tasks are no longer impossible to reorder
- unique arrays remain unchanged

`tests/validation-order.test.ts` also verifies duplicate safe backup slots normalize deterministically.

### 11. Startup now fails closed when local data cannot be safely loaded

After adding validated IndexedDB reads, another bug became visible: the existing initial-load error path completed loading and could render the normal app with an empty-looking task array even though unreadable/corrupt records still existed in IndexedDB.

That could allow a user to create new data while old hidden data remained in the same database.

`src/App.tsx` now has an explicit `loadFailed` recovery state.

If task/settings loading fails:

- the failure is logged through the redacted logger
- normal task editor is not rendered
- Settings/data mutation controls are not rendered
- the screen states that local data could not be safely loaded
- existing browser data is left in place
- only a reload recovery action is provided

No automatic deletion or repair occurs.

New `e2e/corrupt-local-data.spec.ts`:

- creates a current-schema IndexedDB fixture
- inserts an impossible reminder timestamp
- reloads TaskMint
- verifies the fail-closed recovery heading/body
- verifies reload is available
- verifies Add task/composer controls are absent

### 13. PWA updates no longer auto-reload over unsaved task input

### 14. Browser reminder bursts are bounded

At TaskMint's 100,000-task import boundary, enabling notifications with a large already-due reminder set could previously attempt one browser Notification per due task in a single polling pass.

`src/utils/notifications.ts` now exports:

```ts
REMINDER_NOTIFICATION_BATCH = 5
```

Per polling pass:

- first five due/unnotified tasks may produce individual title-bearing notifications
- all remaining due reminders are represented by one count-only summary notification
- the summary body does not contain those excess task titles
- summarized IDs are marked only when the summary constructor succeeds
- a failed summary leaves those IDs retryable
- individual constructor failures also remain retryable

`tests/notifications.test.ts` covers:

- normal one-time delivery
- constructor failure isolation
- 5 + 1 aggregation
- correct count summary
- all-success notified set
- failed-summary retry semantics

### 15. Seven-day completion statistics exclude future timestamps

Clock skew or imported data can contain a completion timestamp after the supplied current time. Previous statistics checked only the lower bound (`>= sevenDaysAgo`), so a future completion counted as completed in the last seven days.

Current rule:

```ts
completedAt >= sevenDaysAgo && completedAt <= now
```

### 16. Development error logging no longer prints arbitrary exception messages

`logEvent` already redacted sensitive metadata fields, but `logError` still emitted `Error.message` in development. Browser/storage/parser exceptions can include arbitrary internal text and should not be treated as safe diagnostic content.

`src/utils/logger.ts` now logs only:

- known `TaskMintError`: `{ kind: 'TaskMintError', code }`
- other Error: `{ kind: 'Error' }`
- non-Error: `{ kind: 'Unknown' }`

It does not log arbitrary exception messages.

New `tests/logger.test.ts` verifies sensitive sample message content is absent and a known TaskMint error logs only its stable code.

#### Portable reminders

`src/utils/notifications.ts` now selects the appropriate delivery path at runtime:

- Web/PWA => Web Notifications API;
- native => Tauri notification plugin.

The existing reminder privacy/reliability rules remain intact:

- permission is requested only after explicit user action;
- individual reminder delivery remains bounded;
- excess due reminders use a title-free summary;
- failed notifications remain retryable.

`src/App.tsx` now awaits reminder checks and prevents overlapping async polling passes.

TaskMint still does **not** claim OS-level background reminder scheduling after the process is fully terminated. That would require a separate per-platform lifecycle/background design.

#### Portable import/export

`downloadText(...)` is now asynchronous and uses the portable file boundary:

- Web/PWA => Blob + download anchor;
- native => system save dialog + scoped filesystem write.

Settings import behavior is likewise runtime-aware:

- Web/PWA => existing hidden file inputs;
- native => system open dialog + scoped metadata/read access.

Selected native content is routed back through TaskMint's existing validated JSON/CSV import path instead of duplicating validation logic.

The existing browser download lifecycle test was updated to await the portable operation.

#### Native external links

In Tauri builds, delegated anchor handling opens `http:`, `https:`, `mailto:`, and `tel:` destinations through the operating system opener plugin. Internal app navigation is not intercepted.

#### PWA/native update separation

`PwaUpdatePrompt` now returns no service-worker updater inside Tauri. Browser/PWA builds retain the explicit waiting-worker **Update now / Later** flow. Native package updating remains a platform-distribution responsibility.

#### Native CSP/IPC hardening

The original HTML production CSP remains strict for browser/PWA builds.

Tauri's native CSP explicitly allows its IPC schemes, and Vite now performs a native-only build transform so the HTML meta policy also permits:

- `ipc:`
- `http://ipc.localhost`

This avoids the intersection of two CSP policies accidentally blocking native plugin calls while keeping the ordinary web build at `connect-src 'self'`.

Development CSP relaxation remains development-only.

#### Mobile safe-area support

`index.html` now opts into `viewport-fit=cover`.

Added `src/platform.css`, loaded after the shared stylesheet, to respect safe-area insets for:

- sticky top bar;
- workspace horizontal edges;
- footer/home-indicator area;
- modal backdrop;
- toast bottom position;
- narrow-screen topbar padding.

On platforms without insets, CSS `env()` resolves without changing the ordinary desktop/browser layout.

- fixed port 5173;
