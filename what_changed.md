## RC3 hardening completed in this continuation

### Deterministic repository hygiene checks

Added `scripts/check-doc-links.mjs`.

It:

- Recursively checks repository Markdown under root documentation, `docs/`, and `.github/`.
- Ignores external HTTP(S), mailto, telephone, data, and in-page-anchor-only references.
- Ignores fenced code blocks to avoid treating examples as real links.
- Resolves repository-relative links from the source Markdown file location.
- Rejects links that escape the repository root.
- Rejects missing local targets.
- Rejects malformed percent encoding.
- Requires only Node.js and no npm package dependency.

Added `scripts/check-secrets.mjs`.

It:

- Scans tracked-style source/config/docs/test text paths for common credential/private-key patterns.
- Covers private-key headers, common GitHub token formats, AWS access-key IDs, Google API keys, Slack tokens, Stripe live keys, and OpenAI-style secret keys.
- Is a deterministic defense-in-depth check only; it does not replace GitHub secret scanning, provider-side detection, credential rotation, or manual review.
- Never requires sending repository content to a third-party scanning service.
- Must never be tested with a real credential.

`package.json` now exposes:

- `npm run docs:check`
- `npm run secrets:check`

`npm run check` now runs:

1. formatting invariants
2. documentation-link verification
3. common secret-pattern verification
4. ESLint
5. TypeScript project checks
6. Vitest unit/component tests
7. production build

CI now runs documentation-link and secret-pattern checks as explicit named steps before lint/type/test/build/audit.

### Strict validation/data consistency

The existing shared limits in `src/domain/limits.ts` remain the single source of truth:

- task ID: 100 characters
- title: 240 characters
- notes: 20,000 characters
- project: 80 characters
- tags per task: 12
- tag length: 32 characters
- backup/import task count: 100,000
- import file/text size: 25,000,000 bytes/characters at the application boundary

Canonical persisted/restored tag normalization is now locale-independent using Unicode `toLowerCase()` rather than host-locale `toLocaleLowerCase()`.

This prevents stored canonical tag values from varying across operating-system/browser locale settings.

Search remains presentation/runtime locale-aware where appropriate; persisted canonical values are deterministic.

### Test isolation hardening

A real test-isolation defect was found: `tests/task.test.ts` stubbed `crypto.randomUUID` with a fixed value in one test without restoring it, which could influence later test cases.

`src/test/setup.ts` now performs shared after-each cleanup:

- Testing Library DOM cleanup

- spy/mock restoration

Task tests now rely on shared cleanup.

Notification tests retain only notification-specific static call reset and use shared cleanup for globals/mocks.

### Export/download lifecycle hardening

`downloadText(...)` still:

- creates a Blob
- creates a temporary object URL
- creates/clicks/removes a temporary anchor

Object-URL revocation is now deferred to the next timer turn instead of happening immediately after `anchor.click()`.

This avoids premature revocation on slower/browser-specific download pipelines.

`tests/download.test.ts` verifies:

- an object URL is created
- the download anchor is clicked
- the temporary anchor is removed
- the object URL is not revoked before the click turn completes
- the object URL is revoked after timers advance

### Reminder persistence consistency

When editing a task reminder, notification suppression is now reset **only after the changed task is successfully persisted**.

Previously, suppression could be cleared before IndexedDB confirmed the edit. A failed save could therefore cause the unchanged old reminder to become eligible for a duplicate notification.

Current ordering:

1. build updated task
2. determine whether reminder changed
3. persist task
4. only after successful persistence, clear reminder suppression for that task if needed
5. update React state

Backup restore still clears the reminder-suppression set after successful transactional restore because reminder schedules may have changed globally.

### Date rollover/session freshness

A long-running-session bug was found: Today/Upcoming/Overdue views and date-sensitive statistics could remain based on the previous date if TaskMint stayed open across midnight without another application-state change.

`src/App.tsx` now maintains a lightweight current-time state.

It refreshes:

- every 60 seconds
- when the browser window regains focus
- when document visibility changes

The current time is now passed into:

- `filterAndSortTasks(...)`
- `calculateStats(...)`
- current local date derivation used by overdue display/export filenames

This keeps date-sensitive views/statistics fresh while the app remains open.

`tests/task.test.ts` now proves a task that is in Today before midnight moves out of Today and into Overdue after the date advances.

The execution sandbox still cannot resolve external Git/npm hosts reliably through its shell network path.

Consequences:

- A clean shell clone cannot be used as the authoritative workspace here.
- `npm install` cannot complete from the public registry in this environment.
- A real `package-lock.json` cannot be generated here.
- Full dependency-backed ESLint/Vitest/Vite/Playwright execution cannot be claimed locally.
- GitHub repository reads/writes are performed through the authenticated GitHub connector.
- Hosted GitHub Actions must provide clean-network dependency-backed verification.

No lockfile, screenshot, test result, or release success has been fabricated to work around these limitations.

## Known intentional limitations

- Browser reminders are polled while TaskMint is open; reliable closed-app scheduled notification support is not claimed for every browser/OS/PWA combination.
- Browser-local TaskMint data is not application-encrypted at rest; an unlocked browser/OS profile may expose site storage.
- Exported JSON/CSV files are readable outside TaskMint and are governed by the user's filesystem/backup/sharing environment after download.
- Additional locale packs are not shipped in v0.1.
- Full virtualization is not included without benchmark evidence; progressive 100-card rendering is the current bounded presentation strategy.
- Tauri is not included in v0.1.
